Run a suite yourself

Each run's corpus.jsonl (linked above) holds its queries, one JSON object per line. To compare two builds, save this as run.py, run it once per build on the same database, and diff the results:

#!/usr/bin/env python3
"""Run every query of a regression suite on one build and save each result, so that two builds
can be compared with diff:

    run.py corpus.jsonl OLD_BIN_DIR DB_DIR out-old
    run.py corpus.jsonl NEW_BIN_DIR DB_DIR out-new
    diff -r out-old out-new
"""
import json, os, subprocess, sys

suite, bindir, db, outdir = sys.argv[1:]
os.makedirs(outdir, exist_ok=True)
for n, line in enumerate(open(suite)):
    query = json.loads(line)['query']
    try:
        p = subprocess.run([os.path.join(bindir, 'osm3s_query'), '--db-dir=' + db],
                           input=query.encode(), capture_output=True, timeout=300)
        result = p.stdout + p.stderr + b'exit status %d\n' % p.returncode
    except subprocess.TimeoutExpired:
        result = b'killed after 300 s\n'
    # The generator line names the build, so it differs between any two builds.
    result = b'\n'.join(l for l in result.split(b'\n') if b'generator' not in l)
    with open(os.path.join(outdir, '%04d.txt' % n), 'wb') as f:
        f.write(query.encode() + b'\n----\n' + result)

Any file that differs shows the query and how its output changed. It works on any database, not only the one the suite was selected on, though queries find the most data on a database of the same region, with history and areas. A query near its [timeout:] can differ between runs, since the timeout message includes the elapsed time.
